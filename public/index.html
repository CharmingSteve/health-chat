Guides

What you can ask
  • Trends: weight, steps, sleep, calories, and blood markers over time (for example HbA1c, LDL, sodium).
  • Relationships: calories against weight, or steps against resting heart rate. These are correlations with sample sizes, not causes.
  • Out-of-range labs: which values fell outside the reference range, with dates.
  • Timelines: what was recorded around a date.
  • Gaps: tests not repeated, and days with no data.

Not available yet: these answers need ingested data and the query tool, which are still to be built.

How an answer is made
  • Numbers come from SQL over your tables, not from the model's memory.
  • Every answer shows the SQL or the document page it came from.
  • You can rerun the SQL yourself and compare the result.
How to read a trend
  • Check the number of data points. One value is a snapshot, not a trend.
  • Check for gaps. A missing day is unknown, not zero.
  • Lab values are one-day snapshots. Compare with the reference range and the lab's own units.
How to read a correlation
  • A correlation shows two things moving together. It does not show that one causes the other.
  • Small samples and shared causes (for example, heat on both training and cramps) can mislead.
  • Each correlation shows its sample size.
Sodium: what the data can and cannot show
  • Blood sodium and potassium come from lab tests on specific days.
  • Salt intake is not recorded in the diet log, so salt intake cannot be measured here.
  • Any sodium answer will say: "blood sodium only".
Blank days are unknown, not zero
  • A day with no entry is not treated as "no symptoms" or "zero calories".
  • Answers state how many days were logged out of the period.
Adding data
  • Daily diet: comes from the stuntman-diet nightly export (not built yet).
  • Apple Watch: export from the iPhone and upload to the apple-health bucket (not built yet).
  • Medical files: Clalit exports and hospital PDFs are uploaded to the medical bucket (not built yet).
What is not used
  • Only folders on the ingest allowlist are read. Anything else is ignored.
  • No other people's data is used.
Where your data lives, and how long it is kept
  • Raw sources (not changed by the app): the Apple Health bucket, the medical bucket, the stuntman-diet puddle bucket, and the diet bucket copy.
  • Derived tables (Parquet): the tables bucket, under diet/ and apple/. Each run overwrites the current files.
  • Old versions of table files are deleted after 30 days. Athena query results are deleted after 7 days.
  • Current tables and raw copies are kept until you delete them.
  • Every bucket is private, encrypted with AWS-managed keys, and versioned. Ledgers in ledger/ record which source files each run read.
What "import" means here
  • Upload copies a file into a bucket. Nothing is read or changed.
  • Import (npm run ingest) reads the source files, checks and cleans them, and writes Parquet tables. It can run again safely: the source is re-read and the tables replaced.
  • Import never changes a source file. It stops with an error on a row it cannot read, rather than guessing.
  • Import runs on your machine with the click profile, because the 1.6 GiB Apple export is too large for a Lambda run.
Apple Health: read before you total anything
  • The export holds records from every source (iPhone, Apple Watch, and apps). Adding them up directly can count the same activity twice.
  • Totals should use one source per time window, or the Health app's own statistics. The app does not yet de-duplicate, so its totals are raw sums.
  • Every workout type is kept: walking, skating, CrossFit, and others.
  • Routes are GPX tracks. Distances are summed between points, so they are approximate.
  • ECG recordings are kept as samples in microvolts. Classifications come from the watch, not from a doctor.
Diet data: sources and corrections
  • Two sources: the legacy master CSV (May 2025 to March 2026) and the stuntman-diet nightly export (from October 2026).
  • The two sources have no days in common, so nothing is counted twice.
  • Superseded entries are kept and marked, so you can see what was corrected.
  • Seven identical entries dated 5 January 2025 were excluded by a named rule, and the count is recorded in the ledger.
  • Legacy dates are day-first (01/05/2025 is 1 May 2025).
Medical disclaimer
  • This app is not medical advice and does not diagnose or treat.
  • Seek urgent care for severe or sudden headache, confusion, vomiting, fainting, or chest pain.
  • Discuss supplement doses, potassium, and kidney-related results with a doctor.
